## Ingress and routing

1. [`_normalize_processing`](https://github.com/StegVerse-org/StegVerse-SDK/blob/f5d9fdcc089bc8becdbc23a6107dab978dc15f56/stegverse/manifest_contract.py#L41-L77) accepts omission of `processing` only for the canonical governance route; a non-governance or future route requires an explicit processing declaration. Where `processing` is supplied, its `route_id` must exactly equal `extensions.stegverse_route.route_id`. These are implementation validation rules, not proof that the selected processor executed. This corrects the generated "structural validation therefore runtime dispatch" implication.
2. [`build_manifest`](https://github.com/StegVerse-org/StegVerse-SDK/blob/f5d9fdcc089bc8becdbc23a6107dab978dc15f56/stegverse/manifest_builder.py#L211-L227) accepts source framework, output ID, data and processor request and separately creates a manifest; its invocation is not governed execution. The first-party [source-drift corrections](CURRENT_SOURCE_DRIFT_CORRECTIONS.md) retain the exact moved helpers rather than silently redirecting old DeepWiki references.
3. [`_partition_text`](https://github.com/StegVerse-org/StegVerse-SDK/blob/f5d9fdcc089bc8becdbc23a6107dab978dc15f56/stegverse/purpose_bound_worker_processor.py#L50-L64) builds ordered contiguous text segments and checks that concatenating their text reconstructs the input; that local invariant does not prove independent worker scheduling or genuine concurrent execution.

## Non-authorizing request and execution boundaries

4. [`_validate_handler_result`](https://github.com/StegVerse-org/StegVerse-SDK/blob/f5d9fdcc089bc8becdbc23a6107dab978dc15f56/stegverse/universal_entry_dispatch.py#L44-L68) recognizes exactly four local statuses: `completed`, `degraded`, `unavailable`, `failed_closed`. It defaults four escalation flags to false and rejects attempts to set authority, execution, custody transfer or admissibility determination to anything else. A returned local status does not authenticate downstream transitions.
5. [Security-posture request validation](https://github.com/StegVerse-org/StegVerse-SDK/blob/f5d9fdcc089bc8becdbc23a6107dab978dc15f56/stegverse/security_posture_request.py#L7-L60) restricts supported tiers to `SECURE`, `HIGH` and `HIGHEST`, requires `authority_effect = NONE_REQUEST_INPUT_ONLY`, and forbids a selected tier when `selection_present` is false. It does not authorize a security posture or replace Interlock/InTr adjudication.
6. [The atomic task/worker state graph](https://github.com/StegVerse-org/StegVerse-SDK/blob/f5d9fdcc089bc8becdbc23a6107dab978dc15f56/stegverse/atomic_task_worker_processor.py#L137-L186) **declares**, rather than executes, an ordered series from WorkerCoordinator claim/fence through terminal retirement; its returned graph explicitly records `adapter_executes_lifecycle: false` and `authority_effect: NONE_GRAPH_DERIVATION_ONLY`. Test fixtures or graph construction are not evidence of actual WorkerCoordinator check-in, Master Records reconstruction or a deployed worker.
7. [Stage-1 organization receipt review](https://github.com/StegVerse-org/StegVerse-SDK/blob/f5d9fdcc089bc8becdbc23a6107dab978dc15f56/stegverse/stage1_org_receipt_review.py#L1-L6) describes itself as read-only with no network, ledger, credential, execution or custody access; supplied snapshots cannot authenticate their own origin. The canonical ledger and Master Records must instead be queried through their existing authorized owner.
8. [Governance Reference Graph constants](https://github.com/StegVerse-org/StegVerse-SDK/blob/f5d9fdcc089bc8becdbc23a6107dab978dc15f56/stegverse/governance_reference_graph.py#L23-L29) deny governance authority from graph representation, hierarchy, composition, SDK interpretation or unknown relations. A relationship graph is a descriptive projection, not the transition authority.

## HTTP, presentation and disclosure distinctions

9. [The local Ecosystem Chat HTTP adapter](https://github.com/StegVerse-org/StegVerse-SDK/blob/f5d9fdcc089bc8becdbc23a6107dab978dc15f56/stegverse/ecosystem_chat_pipeline_http.py#L12-L35) rejects non-POST methods with 405, wrong paths with 404 and malformed JSON with 400. For a parsed local pipeline response, it returns 202 when intake `accepted` is true and 422 otherwise. Those returned integer codes describe the local function; neither a real HTTP deployment nor a completed external write follows from the source alone.
10. [The Ecosystem Chat pipeline](https://github.com/StegVerse-org/StegVerse-SDK/blob/f5d9fdcc089bc8becdbc23a6107dab978dc15f56/stegverse/ecosystem_chat_pipeline.py#L16-L36) creates a persistence plan, constructs a destination binding and passes the plan to a supplied write adapter. It does not independently demonstrate durable organizational storage or authenticated far-side custody.
11. [Publisher return binding](https://github.com/StegVerse-org/StegVerse-SDK/blob/f5d9fdcc089bc8becdbc23a6107dab978dc15f56/stegverse/publisher_return_binding.py#L1-L33) is limited to SDK caller-return assembly; the module explicitly does not invoke Publisher, LLM Adapter, Interlock/InTr or a far-side transition. The named ready state is not proof of completed communication.
12. [Manifest navigation guidance](https://github.com/StegVerse-org/StegVerse-SDK/blob/f5d9fdcc089bc8becdbc23a6107dab978dc15f56/stegverse/governance_navigation.py#L86-L105) distinguishes caller-facing return/label projection from underlying governed transitions and states that a receipt locator is not an authority token. This is a documented contract, not evidence that any particular original runtime receipt currently exists.

## Curatorial decision

The retained per-occurrence ledger contains original source pointers even when unsupported, so readers can reconstruct why a claim was accepted only at the narrow declaration level or rejected. For generated diagrams, high-level multi-repository assertions, status-to-authority promotions and runtime-completion claims, **omit** any unsupported implication until a specific implementation plus original authenticated runtime/receipt evidence is available. A syntactically correct GitHub source URL is never itself an approval of the claim or a grant to republish third-party text.
